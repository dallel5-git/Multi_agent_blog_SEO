Neuf agents qui écrivent votre blog,
et vous laissent le dernier mot.

Un pipeline multi-agents orchestré par LangGraph qui fait la veille technologique mondiale et tunisienne, choisit un sujet non redondant, rédige l'article en français, vérifie son exactitude technique, optimise son SEO, le passe au crible d'une checklist de qualité — puis vous demande confirmation sur Telegram avant toute publication. Le tout avec des services 100 % gratuits, sans jamais sortir une carte bancaire.

Un run dure de 3 à 8 minutes hors attente de validation, et consomme 7 à 9 appels LLM — soit environ 0,6 % du quota Gemini gratuit journalier.

Le moment décisif : votre validation Telegram

C'est la règle métier centrale du projet. Rien n'est jamais publié sans votre clic. Un brouillon est systématiquement écrit dans storage/drafts/ avant même la demande — le travail du pipeline n'est jamais perdu, même si Telegram ou Git tombent.

Ce que vous recevez

  • Le titre optimisé, la meta description, le slug, la catégorie
  • Le nombre de mots, le nombre de sections, le score de qualité
  • L'angle tunisien retenu et les avertissements éventuels
  • Un extrait du texte, et le fichier .mdx complet en pièce jointe
  • Trois boutons

✅ Publier (push Git)

  1. Le .mdx est écrit dans content/articles/
  2. L'image de couverture est copiée dans public/covers/
  3. git add des deux fichiers uniquement
  4. git commit -m "content: …"
  5. git push origin main
  6. Vercel déploie automatiquement
Statut du run : published · notification avec l'URL de l'article

❌ Garder en local

  1. Le .mdx est écrit dans content/articles/
  2. L'image de couverture est copiée
  3. Aucun commit. Aucun push.
  4. Vous relisez, corrigez, et poussez vous-même quand vous voulez
Statut : saved_locally · Telegram vous renvoie la commande git prête à coller

🔁 Faire réécrire

  1. Rien n'est écrit dans le blog
  2. L'article repart à l'agent 4 avec un feedback
  3. Nouvelle passe : relecture, SEO, Quality Gate
  4. Nouvelle demande de validation
Boucle bornée, retour automatique au flux normal ensuite

Anti-doublon sémantique

  1. À chaque run, tous les .mdx du blog sont relus et réindexés — vous avez pu en ajouter un à la main entre deux runs.
  2. Chaque article est encodé en vecteur : titre + description + catégorie + tags, avec all-MiniLM-L6-v2 en local sur CPU.
  3. Le Keyword Analyst encode son sujet candidat et interroge ChromaDB.
  4. Similarité cosinus ≥ 0.85 → sujet refusé, nouvelle proposition demandée avec une température plus élevée. Jusqu'à 3 tentatives.
  5. Après écriture réussie, l'agent 9 ajoute le nouvel article à l'index.

Tenir dans les quotas

  • Rate limiter à double fenêtre (minute + jour) qui bloque avant l'appel plutôt que d'encaisser un 429. L'état journalier est persisté sur disque : redémarrer le process ne remet pas le compteur à zéro.
  • Bascule Gemini → Groq : sur 429, bascule immédiate et Gemini est écarté pour le reste du run. Sur panne réseau, bascule aussi mais Gemini est retenté au coup suivant.
  • Retry avec backoff exponentiel et jitter sur tous les appels réseau.
  • 7 à 9 appels LLM par run (jusqu'à 13 avec deux révisions), soit ~0,6 % du quota Gemini gratuit pour un run chaque semaine.

Sécurité

  • Aucune clé en dur. Tout passe par des variables d'environnement ; .env est dans .gitignore et la CI vérifie qu'il n'est pas versionné.
  • Détection de secrets dans l'article généré par l'agent 5 : motifs Google, OpenAI, Groq, GitHub, Telegram, Slack. Un secret en clair est un blocage.
  • Jamais de git add -A : le bot ne commite que les fichiers qu'il a produits, pour ne pas emporter votre travail en cours.
  • Écriture atomique (fichier temporaire + os.replace) : Next.js ne peut jamais lire un .mdx à moitié écrit.
  • Identité Git locale au dépôt, jamais en configuration globale.
